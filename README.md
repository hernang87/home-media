# Home Media

A small media server for your home network. It scans a folder of movies and shows, plays them on a Chromecast, and is controlled from a phone page or a macOS desktop app.

- **`mediad`**: the daemon. Scans `MEDIA_DIR`, serves files with direct play or on-demand HLS transcoding (ffmpeg), converts subtitles to WebVTT, and casts to Chromecast. The CASTv2 client is hand-rolled and uses the stock Default Media Receiver.
- **`homemedia-app`**: a Fyne desktop client for macOS. It starts `mediad` when none is running.
- **Phone page**: open `http://<your-mac>:8200/` on the same Wi-Fi to browse and cast. The app's Phone tab shows a QR code.

## Requirements

- Go (see `go.mod`)
- `ffmpeg` and `ffprobe` on `PATH`
- A C toolchain for the desktop app (Fyne uses cgo)
- macOS for the desktop app and the launchd service. `mediad` itself is plain Go.

## Build and run

```sh
go build -o bin/mediad ./cmd/mediad
go build -o bin/homemedia-app ./cmd/homemedia-app
cp .env.example .env     # then edit
bin/mediad               # run from the repo root: reads ./.env, writes ./data
```

Other commands:

- `bin/mediad doctor` checks your setup.
- `bin/mediad install` / `uninstall` manage a launchd agent so `mediad` starts at login.
- `bash scripts/package-app.sh` builds `bin/HomeMedia.app`.

## Configuration

Set these in `.env` (see `.env.example`) or the environment.

| Variable | Default | Meaning |
| --- | --- | --- |
| `MEDIA_DIR` | `~/Media`, then `~/Documents/Media` | Folder with your movies and shows |
| `TMDB_API_KEY` | none | Posters and metadata. Without it, artwork falls back to video frames |
| `TMDB_LANGUAGE` | `en-US` | Metadata language |
| `PORT` | `8200` | HTTP port |
| `SERVER_NAME` | `Home Media` | Name shown to clients |

## Security

`mediad` has **no login**. It is meant for a trusted home network.

- It listens on all interfaces but answers only loopback, private (RFC 1918 / unique-local) and link-local addresses.
- `/api/` rejects requests carrying a foreign `Origin` header or a public-looking `Host` name, so a web page open in your browser cannot control your server.
- Media routes (`/file`, `/sub`, `/hls`) allow cross-origin reads, because the Chromecast receiver needs them. Anyone on your LAN who knows an item ID can fetch it.
- Do not port-forward it to the internet.
